Supporting autonomous-flight research at the seam between onboard hardware and ROS2 software - the part where the sim has to actually become a flying airframe.

Overview

AIROU works on small autonomous UAVs spanning perception, control, and flight-test ops. My slice has been the dev loop between simulation and the field - making sure the same autonomy stack that runs in Gazebo can run on a real airframe without surprises.

Problem

UAV autonomy code rots fast when the gap between simulation and field test is wide. Sensor drivers behave differently on hardware. Telemetry streams that are clean in SITL drop packets in the air. We needed a tighter loop that catches regressions before they get to the runway.

Approach

  • Built and maintained ROS2 nodes for sensor integration, telemetry, and bag-recording.
  • Stood up a Gazebo SITL workflow that mirrors the onboard topic graph, so the same code runs in sim and on the airframe.
  • Wrote pre-flight checklists and post-flight log-analysis notebooks to compare sim vs. field telemetry.
  • Helped plan and execute flight tests at the field - ground checks, range ops, debrief.

Outcome

  • Tightened the iteration loop between sim and field - regressions caught earlier, fewer surprises on the runway.
  • Reusable telemetry & log-analysis tooling that other lab members now use on their own platforms.
  • Operational discipline: every flight has a written checklist, a log, and a debrief before anything is flown again.
