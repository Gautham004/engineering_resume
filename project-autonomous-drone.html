Research on a small autonomous UAV - perception, mission planning, and the operational workflow that gets autonomy code from simulation onto a real airframe without surprises.

Overview

The project spans the autonomy stack on a small UAV: sensor integration, a perception pipeline, mission planning, and the ground-test workflow that proves the pieces talk to each other. The goal is a platform that other lab members can pick up, fly, and extend without re-learning the entire stack.

Problem

Autonomous flight code rots fast when the gap between simulation and field test is wide. Sensor drivers behave differently on hardware, telemetry that is clean in SITL drops packets in the air, and mission plans that look fine on a desk fail in the wind. The research needed a tight sim-to-real loop and a flight-test workflow that catches regressions before they get to the runway.

Approach

  • Built and maintained ROS2 nodes for sensor integration, telemetry, and bag-recording.
  • Stood up a Gazebo / PX4 SITL workflow that mirrors the onboard topic graph, so the same code runs in sim and on the airframe.
  • Prototyped a perception pipeline using OpenCV for onboard image processing tasks.
  • Wrote pre-flight checklists and post-flight log-analysis notebooks to compare sim vs. field telemetry.
  • Helped plan and execute flight tests - ground checks, range ops, debrief.

Contribution

  • Set up the ROS2 autonomy node graph and the SITL-to-onboard parity workflow.
  • Built and tuned the perception pipeline for the platform's onboard compute budget.
  • Drove flight-test ops: checklists, log capture, and post-flight analysis.

Outcome

  • Tightened the iteration loop between simulation and field - regressions caught earlier, fewer surprises on the runway.
  • Reusable telemetry & log-analysis tooling that other lab members now use on their own platforms.
  • Operational discipline: every flight has a written checklist, a log, and a debrief before anything is flown again.

What I Learned

  • Autonomy is mostly an operations problem - the algorithms matter, but the workflow that runs them matters more.
  • Sim parity is worth the up-front cost; it pays back the first time it catches a regression.
  • Field test exposes assumptions that no amount of static analysis can find.
